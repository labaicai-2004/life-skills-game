# 生活小能手离线使用与 iPad 安装设计

日期：2026-10-03。状态：三部分交互设计已获口头确认，本文待用户书面审阅。目标是让教师首次联网打开后，把现有三项生活技能训练完整保存在 iPad 上；之后在无网络时仍能进入网页、完成三关各七步、播放正式语音与背景音乐，并在设备本地保存研究记录。儿童端的浮岛首页、游戏画面、手势、动画、提示、奖励及 21 步逻辑保持不变。

## 范围与现状

应用保持原生 HTML、CSS、JavaScript，不引入框架或运行时 CDN。`index.html` 仍承载应用代码；仅为离线安装增加根目录的 `manifest.webmanifest`、`service-worker.js` 与本地图标资源。当前运行资源包括 `assets/` 中 13 张 PNG、正式 `voice/v00.wav` 至 `v35.wav` 共 36 条、`music/xylophone.wav`。尚未通过整套听感验收的自然女声候选不进入缓存，也不替换正式录音。

当前页面从 Google Fonts 加载 ZCOOL KuaiLe；这条远程依赖必须在离线验收前消除。首选在确认许可和实际体积后把同款字体文件放到项目内，并保持既有字形与回退字体顺序；若不能合法或可靠地本地化，明确使用已存在的系统中文回退字体，并通过截图检查可见差异。不能把外部字体请求计入“离线已就绪”。研究数据当前存在 `researchRecords`、`session_summaries`、`researchParticipants`、`researchSession` 和 `life-skills-records` 等本地键；现有备份只覆盖其中三项，恢复会直接覆盖同名数据。本设计仅完善数据保护与迁移，不变更研究记录字段、提示规则或实验阶段控制。

## 组件与职责

`manifest.webmanifest` 定义应用名称、独立显示模式、主题色、以 `/life-skills-game/` 为生产作用域的起始地址，以及本地 192/512 像素图标。路径采用相对项目根目录的形式，保证 GitHub Pages 子路径和本地 HTTP 预览都可用。iPad Safari 由教师通过“分享 → 添加到主屏幕 → 添加”安装；其他浏览器如提供安装入口则展示对应提示，没有入口时只给手动说明。安装说明和状态入口只放在教师/研究者区域，不在儿童训练中弹窗。

`service-worker.js` 只负责同源静态应用资源：首次安装预缓存 `index.html`、清单、图标、所有实际使用的图片、36 条正式语音、木琴音乐及选定的本地字体。缓存清单有明确版本号，更新时先建立并验证完整的新版本缓存；任一必需资源失败时不宣称离线就绪，并保留仍可用的旧版本。导航请求在离线时返回已缓存的首页；静态资源从当前完整版本缓存读取，避免页面和资源跨版本混用。研究数据、导出文件、外部网址均不进入 Service Worker 缓存。首次缓存约为数十 MB，实际值以资源清单测量；若浏览器容量不足，教师看到失败原因和重试入口，不能把“已安装”误报为“可离线”。

`index.html` 中新增小型教师端协调逻辑：注册与查询 Service Worker、显示“准备中／已就绪／失败可重试／有新版待确认”等状态，提供安装指引、更新确认和备份/导入入口。状态以 Service Worker 对当前版本完整缓存的核验结果为准；没有 Service Worker 支持或处于 `file://` 时明确说明须使用 HTTPS 线上地址或本地 HTTP 预览。不能只凭 `navigator.onLine` 或安装图标判断离线可用。儿童端只继续使用现有相对路径加载资源。

## 更新与训练保护

新网页发布后允许浏览器在后台下载完整新缓存，但不在训练进行中调用 `skipWaiting()`、刷新页面或切换可见画面。教师端显示“新版已准备好”；教师结束训练并主动点击“应用更新”后，才请求等待中的 Service Worker 激活，并在安全时机刷新。若存在仍在训练的同源标签页或主屏幕实例，更新继续等待，避免旧页面与新资源交叉；不能确知其他实例状态时采取保守等待并提示关闭其他训练窗口。更新失败时继续使用旧缓存并允许教师重试。新版本首次成功激活后才清理过期静态缓存，绝不清理 localStorage 研究数据。教师手动更新前应能先导出备份，但备份不作为下载新资源的前提。

## 本地研究数据与迁移

Safari 标签页与 iPad 主屏幕独立应用不假定共享 localStorage。迁移流程为：教师在原 Safari 页面导出 JSON；在新安装的主屏幕应用中选取该文件；页面先校验文件类型、顶层结构和各键的数据类型，展示来源时间、记录数量、参与者数量以及与现有数据的重复/冲突数量；教师确认后才导入。默认保留目标端已有记录，不作静默整库覆盖。`researchRecords` 和 `session_summaries` 按稳定字段构成的记录签名合并，完全相同的记录跳过；同一会话或步骤标识但内容不同的记录不自动覆盖，列出冲突并停留在预览页，需教师选择取消或另外备份后再处理。`researchParticipants` 保留既有编号并合并新编号；`life-skills-records` 的历史计数不累加重复完成记录，冲突时保留目标端原值并明确提示。`researchSession` 只作为最近一次设置参考，不恢复为“正在训练”的活动会话。旧版三键备份也可读；缺失的新字段按空集合处理，不删除目标端数据。

导出包增加格式版本、导出时间及上述五类本地键；对旧备份保持兼容读取。教师端“上次备份”和“备份后新增 Session 数”仅是本设备的提醒：点击导出只能确认浏览器发起下载，不能证明文件已永久保存；提示教师检查下载文件。计数依据本地新建会话的稳定 ID，而非游戏步骤条数，浏览器清理存储后该提醒也可能丢失。数据仍只保存在本机及教师主动导出的文件中，不上传服务器。导入写入失败（包括容量不足）必须报告失败并尽可能恢复导入前快照，不能显示虚假的成功；实施时用隔离测试数据验证这一点。

## 验收与边界

自动检查覆盖资源清单完整性与实际引用一致、36 条录音和音乐、缓存中断/重试、新旧版本切换、教师确认门槛、旧备份兼容读取、新备份合并与冲突提示、容量不足时的数据保护，以及研究记录结构不变。桌面浏览器以真实点击/拖动完整走通三关 21 步，检查声音、音乐、动画、奖励和研究记录；再用离线模式冷启动、退出重开、刷新和失败资源模拟复查。iPad Safari 与“添加到主屏幕”后的独立应用都需实体设备验收：首次联网等待就绪、开启飞行模式后冷启动、走完 21 步、播放语音与音乐、保存并导出研究数据；Safari 旧记录导出后在主屏幕应用预览导入，确认数量与冲突结果。未完成 iPad 真机验证前不得宣称“iPad 离线全流程已通过”。

本轮不重做儿童界面，不改三关动作判定、提示层级、实验阶段、研究数据 schema 或尚未完成的自然女声替换；PWA 不保证浏览器永久保留缓存和 localStorage，因此教师仍需定期导出备份。上线时先在本地和测试浏览器验证，得到用户确认后再推送 GitHub Pages。
